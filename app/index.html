From source code to your browser in four steps

Each step hands one artifact to the next. The same image runs on a laptop and on EC2, so what you test locally is what ships.

  1. Source code

    The page and its Dockerfile live in a public GitHub repository.

    git push origin main

  2. Docker image

    Nginx on Alpine Linux plus this page, built into one portable image.

    docker build -t deployflow .

  3. AWS EC2

    The instance runs the container and maps host port 8081 to Nginx on port 8081.

    docker run -d -p 8081:8081 deployflow

  4. Browser

    Anyone can open the instance's public address on port 8081.

Three tools, each with one job

No framework, no build step. A single HTML file, a short Dockerfile, and the infrastructure to run it.

Docker

Packages the web server and the page into an image that runs the same way on any machine with Docker installed.

  • Base image: nginx:alpine
  • Health check confirms Nginx is answering

AWS EC2

A small virtual server in the cloud with a public IP address. It runs Docker and keeps the container online.

  • Security group opens TCP 8081 to everyone
  • SSH limited to a single IP address

GitHub

Holds the source in a public repository. The server clones it, so every deployment starts from a known commit.

  • Code and Dockerfile versioned together
  • Redeploy with git pull and a rebuild

What actually runs on the server

One container, one process, one open port. Here is how a request reaches this page.

The image

Docker starts from the official nginx:alpine image, which is small because Alpine Linux is small. The build copies app/index.html into /usr/share/nginx/html, the folder Nginx serves. It also swaps in a short Nginx config that listens on port 8081, and nginx -t checks that config during the build, so a mistake fails the build instead of the server.

The port mapping

Inside the container Nginx listens on port 8081. Running with -p 8081:8081 tells Docker to forward port 8081 on the EC2 host to the same port in the container. The security group allows inbound TCP 8081, so the request can reach the host at all.

Staying up

The container runs detached with --restart unless-stopped, so it comes back after a crash or a reboot of the instance. The health check lets docker ps show whether Nginx is actually answering, not just whether the process exists.
